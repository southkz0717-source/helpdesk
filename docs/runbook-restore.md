# Runbook RB-01: өтінімдерді сақтық көшірмеден қалпына келтіру

| | |
|---|---|
| Қашан қолданылады | Өтінімдер жоғалды немесе бұрмаланды (релиз жоспарының 4-кері қайтару критерийі, P1). Немесе ай сайынғы оқу-жаттығу |
| Кім орындайды | Кезекші. Жүйені **бірінші рет көріп тұрған адам** да орындай алады |
| Қанша уақыт | ~10 минут. Нысана RTO ≤ 15 минут |
| Қандай деректер жоғалады | Соңғы сақтық көшірмеден кейін жасалған өтінімдер. Нысана RPO ≤ 24 сағат (күнделікті көшірме) |
| Соңғы тексеру | 6-бөлімдегі журналды қараңыз |

> Бұл нұсқаулық түнгі үште жұмыс істейтіндей жазылған: әр қадамда нақты команда және **күтілетін нәтиже** бар.
> Нәтиже күтілгеннен өзгеше болса — тоқтаңыз және 5-бөлімге өтіңіз.

## 0. Дайындық

Командалар Helpdesk репозиторийінің түбірінде, `docker-compose.yml` жанында орындалады.
Мысалдар PowerShell-ге арналған. Linux/macOS-та да дәл солай жұмыс істейді.

```powershell
cd C:\dev\helpdesk
docker compose ps helpdesk
```

**Күтілетін нәтиже:** `helpdesk` жолы, `STATUS` бағанында `Up` немесе `Up (healthy)`.
**Басқаша болса:** Docker Desktop іске қосылмаған — оны ашып, жасыл белгіні күтіңіз.

## 1. Сақтық көшірме жасау

Бұл бөлім **әр релизден бұрын** және **күн сайын** орындалады. Қалпына келтіру кезінде оны да міндетті түрде орындаңыз: бұзылған деректердің өзін де сақтап қою керек.

```powershell
mkdir backups -Force
$ts = Get-Date -Format "yyyyMMdd-HHmm"
docker compose exec helpdesk python -c "import sqlite3; s=sqlite3.connect('/data/helpdesk.db'); d=sqlite3.connect('/data/backup.db'); s.backup(d); d.close(); print(s.execute('select count(*) from tickets').fetchone()[0])"
docker compose cp helpdesk:/data/backup.db "backups/helpdesk-$ts.db"
docker compose exec helpdesk rm /data/backup.db
```

**Күтілетін нәтиже:** бірінші команда өтінімдер санын шығарады (мысалы `214`). `backups\` қалтасында `helpdesk-ЖЖЖЖААКК-ССММ.db` файлы пайда болады.

> **Неге `docker cp helpdesk:/data/helpdesk.db` емес?** v0.4.0-ден бастап база **WAL режимінде** жұмыс істейді: соңғы өзгерістер бөлек `helpdesk.db-wal` файлында тұрады. Тек негізгі файлды көшірсеңіз, соңғы өтінімдер жоғалуы мүмкін. `sqlite3.backup()` сервис жұмыс істеп тұрғанда да толық және келісілген көшірме жасайды.

## 2. Қай көшірмеден қалпына келтіретінді таңдау

```powershell
Get-ChildItem backups\*.db | Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name, LastWriteTime, Length
```

Ақау басталғанға дейінгі **соңғы** көшірмені таңдаңыз. Ақау басталған уақыт инцидент issue-де жазылады.
Көшірмеде қанша өтінім бар екенін тексеріңіз:

```powershell
$backup = "backups\helpdesk-20261118-0930.db"   # <- таңдалған файл
python -c "import sqlite3,sys; print(sqlite3.connect(sys.argv[1]).execute('select count(*), max(created_at) from tickets').fetchone())" $backup
```

**Күтілетін нәтиже:** `(214, '2026-11-18T04:29:...')` — өтінімдер саны мен соңғы өтінімнің уақыты (UTC).
**Санның 0 болуы немесе қате шығуы:** бұл файл бұзылған — алдыңғы көшірмені таңдаңыз.

## 3. Қалпына келтіру

**3.1. Қазір не болып жатқанын хабарлау.** Команда арнасына жазыңыз:
*«Helpdesk сақтық көшірмеден (<файл>) қалпына келтірілуде. ~10 минут қолжетімсіз болады.»*

**3.2. Қазіргі (бұзылған) деректерді сақтау** — 1-бөлімді орындаңыз. Бұзылған көшірме талдауға керек болады.

**3.3. Сервисті тоқтату:**

```powershell
docker compose stop helpdesk
```

**Күтілетін нәтиже:** `Container helpdesk  Stopped`.

**3.4. Көшірмені томға салу және WAL файлдарын жою:**

```powershell
docker compose run --rm --no-deps -v "${PWD}\backups:/backups" --entrypoint sh helpdesk -c "cp /backups/$(Split-Path $backup -Leaf) /data/helpdesk.db && rm -f /data/helpdesk.db-wal /data/helpdesk.db-shm && ls -l /data"
```

**Күтілетін нәтиже:** тізімде тек `helpdesk.db` тұр, өлшемі көшірме файлымен бірдей. `-wal` және `-shm` файлдары жоқ.

> **Неге `-wal` файлын жою керек:** ескі WAL файлы қалса, SQLite іске қосылғанда оны жаңа базаға «қолданып», деректерді бұзады.

**3.5. Сервисті іске қосу:**

```powershell
docker compose start helpdesk
```

## 4. Көмектескенін қалай білуге болады

```powershell
curl.exe -s http://127.0.0.1:8000/health
curl.exe -s http://127.0.0.1:8000/api/stats
```

**Күтілетін нәтиже:**

- `/health` → `{"status":"ok","version":"…","persistent_storage":true}`
- `/api/stats` → `"total"` 2-бөлімдегі өтінімдер санына тең

Содан кейін браузерде http://localhost:8000 ашып, соңғы өтінімдердің бірін ашыңыз.

**Бәрі дұрыс болса:**

1. Арнаға жазыңыз: *«Helpdesk <файл> көшірмесінен қалпына келтірілді. <уақыт> кейін жасалған өтінімдер жоғалды — тізімі инцидент issue-де.»*
2. Инцидент issue-ге қалпына келтіру уақытын жазыңыз.
3. Жоғалған өтінімдердің иелеріне хабарлаңыз. Олардың тізімі 3.2-бөлімде сақталған бұзылған көшірмеден алынады.

## 5. Көмектеспесе

| Белгі | Не істеу керек |
|---|---|
| `docker compose start` кейін контейнер бірден тоқтайды | `docker compose logs helpdesk --tail 50`. `database disk image is malformed` болса — 3.4-ті басқа (алдыңғы) көшірмемен қайталаңыз |
| `/health` → `"persistent_storage": false` | Контейнер томсыз іске қосылған (#7 инцидент). `docker compose down`, содан кейін `docker compose up -d` — **`docker run` емес** |
| `total` күтілгеннен аз | Қате көшірме таңдалған — 2-бөлімге оралыңыз |
| Барлық көшірме бұзылған немесе 15 минуттан асты | **Эскалация:** релиз иесіне хабарлаңыз (релиз жоспары, 2-бөлім). Инцидентті P1 ретінде жүргізіңіз. Бұзылған көшірмелерді **жоймаңыз** |

**Runbook-тың өзін кері қайтару** (қалпына келтіру жағдайды нашарлатса): 3.2-бөлімде сақталған көшірмені 3.3–3.5 қадамдары бойынша қайта салыңыз.
