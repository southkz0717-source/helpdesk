# DORA метрикалары: анықтамалар және есептеу

Скрипт: [`scripts/dora.py`](../scripts/dora.py). Деректер GitHub REST API арқылы жиналады,
дашборд matplotlib-те салынады (ақылы BI-сервистер жоқ).

## Жобадағы анықтамалар

| Метрика | Қалай есептейміз | GitHub API |
|---|---|---|
| Жаю жиілігі | Жарияланған GitHub Release саны / апта. Релизді `release.yml` `vX.Y.Z` тегі бойынша жасайды | `GET /repos/{repo}/releases` |
| Коммиттен продқа дейінгі уақыт | Релизге кірген әр коммит үшін: релиз уақыты − коммит авторлық уақыты; медиана | `GET /repos/{repo}/compare/{prev}...{tag}` |
| Сәтсіз өзгерістер үлесі | Кемінде бір инцидент тудырған релиздер үлесі. Инцидент — `incident` белгісі бар issue; ол ашылғанға дейінгі соңғы релизге жатқызылады | `GET /repos/{repo}/issues?labels=incident` |
| Қалпына келу уақыты | Инцидент issue: `closed_at − created_at`; медиана | сол |

## Деңгейлер

| Метрика | Elite | High | Medium | Low |
|---|---|---|---|---|
| Жаю жиілігі | күніне ≥ 1 | аптасына ≥ 1 | айына ≥ 1 | сирегірек |
| Коммиттен продқа дейін | < 1 күн | < 1 апта | < 1 ай | ≥ 1 ай |
| Сәтсіз өзгерістер үлесі | ≤ 5% | ≤ 10% | ≤ 15% | > 15% |
| Қалпына келу уақыты | < 1 сағ | < 1 күн | < 1 апта | ≥ 1 апта |

Шектер DORA-ның жыл сайынғы есептерінде қайта қаралады — өзекті жарияланыммен салыстырыңыз.

## Іске қосу

```bash
pip install -r requirements-dora.txt
python scripts/dora.py --repo OWNER/helpdesk --out docs/dora
```

Нәтиже: `docs/dora/dashboard.png`, `docs/dora/report.md`, `docs/dora/data.json`.
GitHub Actions-та `DORA dashboard` workflow әр дүйсенбі іске қосылады (немесе қолмен — *Run workflow*).

## Инцидентті қалай тіркеу керек

1. Issue ашыңыз, `incident` белгісін қойыңыз (P1/P2 ақау продакшенде).
2. Түзету релизі шыққанда issue-ді жабыңыз — жабылу уақыты қалпына келу уақытын береді.
